# get_inventory 도구 정의서

| 도구 정의서 항목 | 내용 |
|---|---|
| 이름 | `get_inventory` |
| 하는 일 한 문장 | 승인된 창고에 있는 특정 상품(SKU)의 현재 가용 수량을 읽기 전용으로 조회합니다. |
| 쓰는 때·안 쓰는 때 | **쓰는 때**: 사용자가 특정 상품의, 특정 창고 재고 수량을 물을 때.<br>**안 쓰는 때**: 수량을 바꾸는 요청(입고·출고·조정). 창고나 SKU를 모를 때(먼저 묻는다). 주문·배송 상태를 물을 때. |
| 인자 스키마 | `sku`: 문자열, 필수, 3~32자.<br>`warehouse_id`: 문자열, 필수, 허용값 `SEOUL-01`, `BUSAN-02` 두 개만.<br>둘 중 하나라도 없으면 호출하지 않고 사용자에게 묻는다. |
| 반환 형식 | 성공: `sku`, `warehouse_id`, `available_quantity`(수량), `checked_at`(확인 시각) 네 가지만.<br>원가 같은 다른 값은 돌려주지 않는다.<br>실패: `{"error": "오류 코드"}` |
| 실패 정의와 뒤 행동 | `WAREHOUSE_NOT_ALLOWED`(허용 안 된 창고): 다시 호출하지 않고, `SEOUL-01`과 `BUSAN-02` 중 어느 곳인지 묻는다.<br>`INVALID_SKU`(없는 상품 코드): 비슷한 상품을 추측해 고르지 않고, SKU를 확인해 달라고 묻는다.<br>`SERVER_ERROR`(일시적 서버 오류): 한 번만 다시 시도한다. 또 실패하면 멈추고 조회하지 못했다고 알린다.<br>어떤 오류에서도 수량을 짐작해 말하지 않는다. |

## 실패 사례 되돌리기

| 실패 사례 | 비어 있던 칸 | 보완 문장 |
|---|---|---|
| 존재하지 않는 창고 코드를 임의로 넣어 같은 오류를 반복 호출했습니다 | 인자 스키마, 실패 뒤 행동 | 허용되지 않은 창고면 허용 코드를 물어야 하고 다시 호출하지 않습니다. |
| SKU를 모른 채 가장 비슷한 상품을 골라 조회했습니다 | 인자 스키마, 실패 뒤 행동 | SKU는 필수이며, 없으면 상품 식별자를 물어야 합니다. |
| 응답의 내부 원가를 최종 답에 인용했습니다 | 반환 형식 | 가용 수량과 확인 시각만 근거로 씁니다. |

## 실행 전 채점 기준

| 채점 기준 | 통과 조건 | 확인 위치 |
|---|---|---|
| 스키마 준수 | 호출이 `sku` 문자열과 허용된 `warehouse_id`(`SEOUL-01`, `BUSAN-02`)만 사용했다 | 도구 호출 인자 |
| 호출 성공 | 유효한 입력에서 성공 반환 또는 정해진 오류 코드가 남았다 | 도구 응답 |
| 결과 사용 가능성 | 최종 답이 `available_quantity`와 `checked_at`만 근거로 삼았다 | 최종 답 |
| 실패 처리 | 오류 뒤 수량을 짐작하지 않고 정해진 행동을 했다 | 도구 호출, 최종 답 |
