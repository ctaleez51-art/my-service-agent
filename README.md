# 인적공제 안내 챗봇 — 서비스 가이드 챗봇 설계

## 서비스 소개

종합소득세 신고 앱(diy-wai)에 들어갈 상담 챗봇 중 인적공제 부분이다. 신고자가 "우리 어머니도 공제되나요?" 같은 질문을 하면, 국세상담센터 Q&A와 키워드 연말정산 자료에서 근거를 찾아 [ID]를 붙여 안내한다. 2025년 귀속 기준. 이 저장소는 설계 문서이고, 검색 부분은 RAG 과제(`class/rag-chatbot`)에서 따로 만들었다. 설계 패킷은 [design-packet.md](design-packet.md).

## 설계 결정 요약

### 도구를 네 개만 둔 이유

자료 검색, 소득요건 계산, 나이요건 계산, 상담센터 이관의 네 개다. RAG 챗봇 기준 실행에서 작은 모델(qwen3.5:2b)이 600만원과 5,166,667원의 크기 비교를 틀리고(⑤), 자료의 1955년을 2025년으로 바꿨다(②). 그래서 금액·나이 판단만 계산 도구로 떼고, 나머지는 검색 하나로 둔다. 공제 종류마다 도구를 만들면 '쓰는 때'가 겹치므로 나누지 않았다.

### 권한을 나눈 기준

네 도구 모두 읽기만 한다. 신고서에 부양가족을 넣는 쓰기는 챗봇이 아니라 사용자가 신고 화면에서 직접 한다. 공제 여부 최종 확정과 예외 인정은 세금 결과를 바꾸는 판단이라 챗봇이 하지 않고 이관한다.

### 실패 뒤 행동의 근거

빠진 값은 비슷한 값으로 채우지 않고 묻는다. 도구 실습에서 작은 모델이 사용자 값을 비슷한 허용값으로 바꿔 넣은 일(my-agent/traces trace-02~04)이 있었기 때문이다. 자료에 없으면 관계없는 [ID]를 대지 않고 "자료에 없습니다"로 답한다. RAG 기준 실행에서 ⑦, ⑨가 그렇게 틀렸다.

## 실행하지 않은 것과 이유

- 도구 2~4는 만들지 않았다. 과제 범위가 설계이고, 계산 기준값을 자료 조각에서 뽑는 일은 세법 규칙을 사람이 확인한 뒤에 해야 한다.
- 테스트 문항 T1~T8은 돌리지 않았다. 도구가 없어서다.
- 다음에 측정할 지점: 계산 도구를 붙인 뒤 RAG 고정 질문 ②, ⑤의 grounded가 바뀌는지, ⑦, ⑨에서 관계없는 [ID]가 사라지는지.

## my-agent/

실습 1·2의 산출물(재고 도구 정의서와 실행 기록)을 그대로 옮긴 것이다. 이 챗봇과는 다른 도구다.
